Конечная первая версия: REST API на Go, которое сохраняет расходы и категории в PostgreSQL, показывает статистику и запускается через Docker Compose. Фронтенд пока необязателен — запросы можно отправлять через Postman или curl.
1. HTTP-сервер и хранение в памяти
Сначала научись принимать запросы и возвращать JSON.
- Подними сервер через net/http.
- Добавь создание, получение списка и удаление расходов.
- Пока храни расходы в памяти.
- Проверяй входные данные: сумма положительная, дата корректная, описание не слишком длинное.
- Возвращай понятные ошибки и подходящие HTTP-коды.
У расхода будут: id, сумма, категория, дата расхода и описание.
Деньги храни целым числом в минимальных единицах: например, 15990 означает 159 рублей 90 копеек. Для первой версии выбери одну валюту.
Готово, когда: через API можно добавить расход, увидеть его в списке и удалить; некорректный запрос возвращает ошибку.
2. PostgreSQL и основы SQL
Теперь сделай так, чтобы данные сохранялись после перезапуска.
- Запусти PostgreSQL в Docker.
- Создай таблицы categories и expenses.
- Свяжи расход с категорией через внешний ключ.
- Добавь SQL-миграции — файлы с изменениями структуры БД.
- Реализуй запросы создания, чтения, изменения и удаления.
- Передавай значения в SQL через параметры.
- Вынеси настройки подключения в переменные окружения.
Начальная схема:
categories
  id
  name

expenses
  id
  category_id
  amount_minor
  spent_on
  description
  created_at
spent_on — день, когда ты потратил деньги; created_at — момент добавления записи. Это разные вещи: сегодня можно внести вчерашний расход.
Готово, когда: данные переживают перезапуск сервера, а пустую БД можно подготовить миграциями.
3. Полноценное управление расходами
Добавь возможности, которыми уже удобно пользоваться:
Метод и путь	Назначение
POST /expenses	Добавить расход
GET /expenses	Получить список
GET /expenses/{id}	Получить один расход
PATCH /expenses/{id}	Изменить расход
DELETE /expenses/{id}	Удалить расход
POST /categories	Создать категорию
GET /categories	Получить категории


Для списка добавь фильтры по периоду и категории, сортировку и пагинацию:
GET /expenses?from=2026-09-01&to=2026-09-30&category_id=2&limit=20&offset=0
На этом этапе разберёшься с параметрами запросов, JOIN, WHERE, ORDER BY и обработкой отсутствующих записей.
Готово, когда: можно найти расходы нужной категории за месяц и исправить ошибочно введённую запись.
4. Статистика
Добавь два отчёта:
- Общая сумма расходов за выбранный период.
- Сумма расходов по каждой категории за этот период.
Например:
GET /stats/summary?from=2026-09-01&to=2026-09-30
GET /stats/by-category?from=2026-09-01&to=2026-09-30
Считай статистику в PostgreSQL через SUM и GROUP BY. Затем изучи EXPLAIN и посмотри, каким запросам нужны индексы.
Готово, когда: суммы в отчётах совпадают с заранее подготовленным набором расходов, а период без расходов корректно обрабатывается.
5. Docker для всего приложения
PostgreSQL уже работает в контейнере — теперь упакуй и Go-сервис.
- Напиши Dockerfile с отдельными этапами сборки и запуска.
- Добавь приложение и PostgreSQL в compose.yaml.
- Настрой volume для данных БД.
- Добавь .env.example с примером настроек.
- Определи, как запускать миграции и ждать готовности БД.
Готово, когда: после настройки окружения проект запускается через docker compose up --build, а пересоздание контейнеров сохраняет расходы.
6. Пользователи и доступ к данным
Когда основной функционал работает, добавь многопользовательский режим.
- Регистрацию и вход.
- Хеширование паролей.
- Сессии и выход из аккаунта.
- Привязку расходов и категорий к пользователю.

Особенно полезный сценарий: пользователь подставляет в URL идентификатор чужого расхода — приложение должно запретить доступ.
Готово, когда: два пользователя работают независимо и не могут получить или изменить данные друг друга.
